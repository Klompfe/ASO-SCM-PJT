# vision-eval 측정 하네스

작지 AI 판독 정확도를 로컬에서 재는 도구. DB 없음·운영 코드 비호출(읽기 전용). 명령
예시는 `prompt-reports/PR-199-report.md`·`PR-199b-report.md`·`PR-199c-report.md` 참고.

## 암묵 자재 목록(`implicit-items.json`)

정답(골든) 엑셀에는 작지에 글자로 적혀 있지 않아도 당연히 들어가는 자재(사이즈
스티커, 케어라벨 등)가 있다. AI는 작지 이미지만 보고 읽으므로 이런 자재는 애초에
읽을 수 없다 — "인식 실패(`MISSING`)"와 구분해 `MISSING_IMPLICIT`으로 따로 센다.

`scripts/vision-eval/implicit-items.json`에 정답 자재명(첫 줄 한글명 기준) 목록을
적는다:

```json
["사이즈 스티커", "케어라벨", "이미지택", "폴리백"]
```

- 비교는 공백·괄호 세부사항을 무시한 정규화 후 **포함(includes)** 여부로 한다 —
  "케어 라벨", "케어라벨(H0N-13)"도 목록의 "케어라벨"과 매칭된다.
- **구체적인 이름만 적을 것.** "라벨", "택"처럼 일반적인 단어를 넣으면 실제로 작지에
  적혀 있는 라벨(예: "핸드메이드 라벨", "메인라벨")까지 암묵 자재로 잘못 분류된다.
  작지에 실제로 적혀 있는 자재는 이 목록에 넣지 않는다.
- 추가하려면 이 파일에 문자열을 더 넣으면 된다(코드 수정 불필요, 재빌드 불필요).
- 이 목록은 라벨 구역(`isLabelZone`, `MAIN+SIZE` 마커 이후) 판별과는 **무관한 별도
  분류**다 — 라벨 구역은 "요척 비교 제외, 존재 여부만 집계"이고, 이 목록은 "작지에
  안 적혀 있어 AI가 원천적으로 못 읽는 자재"를 MISSING에서 분리하는 것이다. 둘이
  겹치는 자재(예: 라벨 구역에 있으면서 암묵 목록에도 있는 이름)가 있어도 서로
  다른 집계라 충돌하지 않는다.
